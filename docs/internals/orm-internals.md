# 🗃️ ORM internals

**Rusjango 0.1.5 · Alpha**

Read the [ORM tutorial](../05-orm-guide.md) for usage. This reference explains model metadata, SQL generation, and connection handling.

## 📁 Module map

| Module | Responsibility |
|---|---|
| [fields.py](../../python/rusjango/src/rusjango/orm/fields.py) | Four field classes and backend SQL types |
| [model.py](../../python/rusjango/src/rusjango/orm/model.py) | Metaclass, field inheritance, registry, table names, and create |
| [query.py](../../python/rusjango/src/rusjango/orm/query.py) | Filters, lazy querysets, and CRUD terminal methods |
| [sql.py](../../python/rusjango/src/rusjango/orm/sql.py) | Quoted identifiers, values, and backend placeholders |
| [connection.py](../../python/rusjango/src/rusjango/orm/connection.py) | SQLite serialization, PostgreSQL pooling, and cleanup |

## 🧱 Model registration

Each concrete model is registered at class creation. It gets its own default table name unless its namespace supplies `_table`.

Field metadata can be inherited. An abstract base can set `_abstract = True` and avoid registering itself. More than one primary key is rejected; there is no automatic ID field.

## 📥 Insert results

SQLite integer primary keys use AUTOINCREMENT. PostgreSQL integer primary keys use GENERATED BY DEFAULT AS IDENTITY.

`INSERT ... RETURNING` reads fields from the insert operation and constructs the returned model. This avoids separate shared `last_insert_rowid` reads.

## 🔗 Connection handling

| Backend | Operation lifecycle |
|---|---|
| SQLite | Acquire shared lock → execute/read → commit or rollback → release lock |
| PostgreSQL | Initialize pool under lock → acquire connection → execute/read → release in finally |

The SQLite lock also protects first connection creation. There is one backend configuration per process.

## 🔎 Query generation

Values use `?` on SQLite and `$n` on PostgreSQL. Identifier quoting doubles embedded quotes. Model/query fields are validated before execution.

UPDATE offsets WHERE placeholders after SET values. Exact-null filters use `IS NULL`.

`first` fetches at most one row; `get` fetches at most two. Update/delete require filters and return driver row counts.

## 🔄 Table creation

The migration entry point imports models and executes `CREATE TABLE IF NOT EXISTS`. Connection cleanup runs even after failure.

Relationships, transaction APIs, tracked migrations, ordering, joins, pagination, and count remain pending.
