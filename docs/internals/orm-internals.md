# ORM internals

Applies to Rusjango 0.1.4 (alpha).

| Module | Responsibility |
|---|---|
| fields.py | Four field classes and backend SQL types |
| model.py | Metaclass, field collection/inheritance, table naming, registry, create |
| query.py | Filter validation, lazy querysets, CRUD terminal methods |
| sql.py | Quoted identifiers, parameterized SQL, backend placeholders |
| connection.py | Serialized SQLite connection, PostgreSQL pool, execution/cleanup |

Each concrete model is registered at class creation. It receives its own default table name unless `_table` is explicitly supplied. Field metadata can be inherited; abstract bases can set `_abstract = True` and are not registered themselves. Multiple primary keys are rejected.

SQLite integer primary keys use AUTOINCREMENT; PostgreSQL uses GENERATED BY DEFAULT AS IDENTITY. INSERT RETURNING retrieves fields from the same insert operation and returns a model instance, eliminating shared last_insert_rowid races.

SQLite execution, result reading, and commit/rollback happen within a shared async lock. The lock also protects first connection creation. PostgreSQL initializes its pool under a lock and releases every borrowed connection in finally.

SQL values use `?` or `$n`. Identifier quoting doubles embedded quote characters; model/query fields are validated before execution. UPDATE offsets WHERE placeholders after SET values. Exact-null filters use IS NULL.

first fetches at most one row and get at most two. update/delete return driver row counts and require filters. A migration run imports models and executes CREATE TABLE IF NOT EXISTS; cleanup runs even after failure.

There is one backend per process and no transaction API, relationship support, schema tracking, automatic primary-key field injection, joins, count API, or queryset pagination.
