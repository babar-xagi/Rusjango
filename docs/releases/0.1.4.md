# Rusjango 0.1.4

Phase 1–3 correctness and documentation release. Rusjango remains alpha.

Published on [PyPI](https://pypi.org/project/rusjango/0.1.4/) and [GitHub](https://github.com/babar-xagi/Rusjango/releases/tag/v0.1.4). The [release workflow](https://github.com/babar-xagi/Rusjango/actions/runs/37332756735) passed all 22 jobs and produced five platform wheels plus a source archive.

## Changes

- Fixed literal route matching, 422 validation errors, 405 `Allow` headers, and empty 204 responses.
- Hardened production Host parsing and kept security headers on rejected requests.
- Added proper ASGI startup/shutdown acknowledgements and database cleanup.
- Fixed per-model table names, concurrent SQLite insert results, null filters, and affected-row counts.
- Fixed PostgreSQL identity keys, update placeholders, and pooled connection release after errors.
- Made Python/Rust scaffolding preserve custom APIs and unrelated settings, reject computed settings before creating files, and honor configured settings paths.
- Embedded Rust CLI templates and propagated migration process failures.
- Added strict schema types, optional fields, independent defaults, nested schemas, lists, and dictionaries.
- Reworked all guides and added regression, live PostgreSQL, distribution, and release gates.

## Compatibility and upgrades

Requires Python 3.11+ and SQLite 3.35+. Install into your project environment:

```bash
pip install --upgrade rusjango==0.1.4
# For PostgreSQL:
pip install --upgrade 'rusjango[postgres]==0.1.4'
```

Invalid JSON schema types now return 422; strings such as `"20"` are not coerced to integers. A field annotated with an optional type still requires a default if callers may omit it.

Older databases affected by the default table-name bug may contain a table named `model`. Back up and inspect existing data, then move rows to the correct app/model tables with explicit SQL. This release does not rename tables or migrate data automatically. `migrate` only creates missing tables.

Custom APIs are preserved by `add orm`. Removing ORM keeps application files, so adapt any ORM-dependent handlers yourself.

## Validation and limits

The local full suite passed 74 tests on Python 3.11 and 3.14, including both CLIs, SQLite, live PostgreSQL, and a real Uvicorn server. Four Rust tests, formatting, lint, source-archive rebuilds, and fresh installed-wheel checks passed. See the [validation record](../11-validation.md) for the exact scope and the release workflow for hosted results.

The Rust runtime remains a placeholder. Auth, admin, OpenAPI, relationships, transactions, tracked migrations, Docker scaffolding, and application test scaffolding are pending. These tests do not establish production readiness or a performance advantage.
