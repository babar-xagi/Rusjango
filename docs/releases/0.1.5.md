# 📦 Rusjango 0.1.5

Phase 4: validation extensions, Docker scaffolding, and application test scaffolding. Rusjango remains alpha.

Published on [PyPI](https://pypi.org/project/rusjango/0.1.5/) and [GitHub](https://github.com/babar-xagi/Rusjango/releases/tag/v0.1.5). The [release workflow](https://github.com/babar-xagi/Rusjango/actions/runs/37439320797) passed all 22 jobs.

## ✨ Added

- Schema `Field` constraints for numeric ranges, collection/string lengths, and full-match regex patterns.
- Synchronous `@field_validator` value transformations and `Schema.validate()` cross-field checks.
- Opt-in `__coerce__ = True` for controlled numeric/boolean string conversion.
- Strict defaults, exact-type union preference, nested error locations, finite float checks, and protection against dictionary-key collisions after coercion.
- `add/remove docker` and `add/remove tests` in both Python and Rust CLIs.
- Shared packaged templates and ownership records that preserve existing or modified files.
- Multi-stage Docker/Compose examples with nonroot execution, explicit allowed hosts, debug disabled, and a persistent SQLite volume.
- Generated ASGI pytest fixtures with an isolated in-memory SQLite database.
- `RUSJANGO_SETTINGS` selection for explicitly configured application instances and migration commands.
- Docker build/run checks in CI, installed-wheel feature checks, and beginner guides for validation, containers, and testing.

## ⬆️ Compatibility

Python 3.11+ and SQLite 3.35+ remain required. Coercion is disabled by default. Existing strict schemas continue to use strict JSON types.

`float` schema fields now reject NaN/infinity and overflow. Private annotations and ClassVar metadata are not schema fields.

Schema `Field` comes from `rusjango` or `rusjango.schema`; ORM field classes remain in `rusjango.orm`.

Add/remove feature commands preserve application settings and dependency files. Removal deletes only unchanged tracked scaffold files. It does not remove running containers or database volumes.

## ✅ Validation
