# 🛡️ Rusjango 0.1.6

Phase 5 adds an admin backend foundation: explicit model registration, permission-gated metadata and data services, and shared admin scaffolding.

Published on [PyPI](https://pypi.org/project/rusjango/0.1.6/) and [GitHub](https://github.com/babar-xagi/Rusjango/releases/tag/v0.1.6). All 22 [release workflow](https://github.com/babar-xagi/Rusjango/actions/runs/37476482332) jobs passed.

## ✨ Added

- Independent AdminSite registries, synchronous factory configuration, and optional installed-app discovery.
- Explicit list/detail field projection, bounded pagination, stable sorting, strict filter allowlists, and escaped substring search on SQLite and PostgreSQL.
- Trusted AdminIdentity subjects with exact per-model view/add/change/delete grants; denied operations stop before database access.
- Read-only defaults and opt-in typed create/update schemas, protected primary keys, rejected unknown inputs, and authorized form metadata.
- `add admin` / `remove admin` in Python and Rust CLIs with shared packaged templates and edited-file preservation.
- Admin tests in fresh wheel and Docker checks, plus a step-by-step [admin tutorial](../17-admin.md).

## 📌 Compatibility and setup

`ADMIN` now accepts `None` or `{"FACTORY": "module:callable"}`. Enable the generated scaffold with `ADMIN = {"FACTORY": "admin:create_site"}` and keep `app.load_installed_apps()` in your entry point.

Registration requires explicit visible fields and a declared primary key. Each optional installed-app admin module defines synchronous `register(site)`. Both CLIs preserve base settings; disable a factory reference before removing its unchanged scaffold.

Admin write schemas reject unknown inputs. This is specific to the admin service; existing API Schema handling retains its behavior. Updates validate the full update schema and apply its defaults.

Use the current CLI for the feature manifest. A separate Rust CLI must be rebuilt to include the new embedded admin template.

## 🧪 Validation

155 tests passed on Python 3.11 and 3.14 with both CLIs and live PostgreSQL. Rust checks, clean source/wheel builds, installed-package checks, and Docker runtime/persistence passed. Hosted results are recorded in the [Phase 5 validation record](../18-phase5-validation.md).

## 🧭 Scope

AdminIdentity is a trusted server-side value, not an authentication provider. No dashboard, login, sessions, or HTTP admin routes are installed. Authentication and permissions integration is the next phase before browser exposure.

The ORM still has no transaction API, relationships, or tracked migrations. Rust request acceleration remains pending.
